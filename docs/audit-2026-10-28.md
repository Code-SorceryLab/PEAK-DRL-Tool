# PEAK audit, 2026-10-28

Branch `USER-STUDY+SPRITIFY` at `4058f4a` (later `03fe611`), whole repo. Read by four reviewers in
parallel (training core; AST and stats; reports and servers; game engines), every finding checked
against the code before it was listed, then a local smoke run of every game through the real entry
points (2 generations, 4 cores, Idle priority).

**What this repo does:** PEAK evolves tiny neural networks (14 to 26 inputs, no gradients) that play
four hand-written game clones (a Mario-like platformer, Meat Boy, Bomberman, Mega Man) as six player
"personas", to measure how hard each level is, and to test whether level mutants change play (the AST
study). Training runs as Slurm arrays on Narval; reports become a static site and paper tables.

**Load assumed:** one researcher, but up to ~1,000 array tasks writing under one shared `runs/` tree on
Lustre, each with 3 to 16 worker processes. Results must be bit-for-bit reproducible from the seed.

Status: **fixed** = changed in this branch and covered by the tests; **open** = in `code/games`, which the
`peak-game-fixes` session is editing now, to fix after it commits; **won't fix** = reason given.

## Must fix

1. **Mega Man's AST trains on the default GA, not its sweep winners** (`code/neuro/ast_eval.py:130, 222`) — fixed
   - **What this is:** the AST retrains each Mega Man section with `balance.py`, then plays each section's best run.
   - **Problem:** this branch never got `9f36170` (on `AL-command-center` only). `retrain_job` skips `--best` for
     Mega Man, so it trains on pop 10 although `ga_best.yaml` says pop 30. Playing then picks legs from every tag,
     so base-retrained and a mutant can play one section with two GA settings.
   - **Fix:** ported `9f36170`: always `--best` for Mega Man, play only `*_best` runs (keeping this branch's
     finished-run filter), with its test line.
   - **If we skip it:** the rerun's Mega Man AST compares agents of mixed GA settings, and is labelled as the GA-best run.

2. **Every Mega Man playtest needs the old hand-picked relay** (`code/neuro/ast_eval.py:229, 362`) — fixed
   - **What this is:** Mega Man plays a relay: one agent per section of the stage.
   - **Problem:** `persona_legs` and `retrain` loaded `runs/megaman/relay.json` and all its agents first, even
     though every leg that plays is replaced. A fresh `runs/` (step 8 starts from one) has no relay, so every
     Mega Man retrain and playtest would crash with FileNotFoundError.
   - **Fix:** build the legs from the stage's own sections (`relay.stage_legs`); only the `base` context variant
     still needs the hand-picked relay, and it is skipped with a message when there is none.
   - **If we skip it:** step 8 dies at the Mega Man AST, after hours of cluster time.

3. **A 1-UP restarts Mario mid-episode and wipes its fitness** (`code/neuro/adapters.py:276`, root in `platformer_core.py:1089`) — fixed
   - **What this is:** training gives Mario one life, so a death ends the episode.
   - **Problem:** a 1-UP (hidden block on 1-1, 100 coins, stomp chains) raises lives to 2. The next death then
     soft-resets to the spawn: fitness drops to the spawn x and the stall rule ends it as STUCK.
   - **Fix:** the adapter pins `lives = 1` before every step (the Sonic adapter already noted the same trap).
   - **If we skip it:** agents that find the 1-UP score worse than agents that don't.

4. **`--best` runs share one folder name across different GA configs** (`code/neuro/balance.py:521`, `ast_eval.py:113`) — fixed
   - **What this is:** `balance --best` trains on `ga_best.yaml` and files probes under `p<pop>g<gens>_best`.
   - **Problem:** the tag names no config. Bomberman's winners changed between 10-23 and 10-26 at the same
     pop size, so new probes would land beside old ones in one report. `agent_dirs` also silently fell back
     to whatever retrained tag it found when the baseline's tag had none.
   - **Fix:** `balance --best` refuses to train into a tag whose probes used another config ("move it aside
     first"); `agent_dirs` uses only the baseline's own tag, so stale agents show as missing.
   - **If we skip it:** reports and the AST quietly mix two GA configs.

5. **Meat Boy's "progress at death" is horizontal position** (`code/neuro/balance.py:160`) — fixed
   - **What this is:** each death's progress feeds the death map, death spread and the B2 verdict.
   - **Problem:** it was `x / level width`. Meat Boy levels climb: a death under the goal of 1-10 read as 7 %.
   - **Fix:** use the game's own `progress` when the episode has one, as `trainer.py` already does.
   - **If we skip it:** every Meat Boy card shows wrong death maps and verdicts.

6. **The RQ2 cosmetic check skipped 24 of 27 cosmetic copies** (`code/stats/ast_metrics.py:345`) — fixed
   - **What this is:** a cosmetic mutant must replay exactly like the original (the determinism check).
   - **Problem:** it tested `v.endswith("cosmetic_tile")`; placed copies are named `cosmetic_tile@<level>`.
   - **Fix:** test the variant's kind, so placed and Mega Man (`s3-`) copies all get the check.
   - **If we skip it:** the paper's "replayed identically on N/N levels" counts only the evaluation levels.

7. **Mega Man replay picks the original's agents by how they play the mutant** (`code/neuro/ast_eval.py:262`) — fixed
   - **What this is:** replay mode plays the original's frozen agents on each mutant (the detector).
   - **Problem:** the best run per section was chosen while the mutant was loaded, so selection favoured agents
     that cope with the change.
   - **Fix:** choose legs on the level they trained on, then play the mutant.
   - **If we skip it:** replay under-reports Mega Man mutants.

8. **The collector persona earns nothing for coins on Mario 1-1 and 1-4** (`code/neuro/adapters.py:119`) — fixed
   - **What this is:** a persona weight pays for its event as a share of the level's total.
   - **Problem:** the total counted only loose `C` coins; 1-1 and 1-4 have none (their coins are in `?` blocks),
     so the coin weight was dead and the collector played like the plain persona.
   - **Fix:** count coin `?` blocks too (a multi-coin brick counts once).
   - **If we skip it:** collector results on those levels measure the wrong persona.

9. **Mutants go stale silently when a level file changes** (`code/games/eval_mutants.py:416, 504`) — open (code/games)
   - **What this is:** each mutant is a copy of its level with one change, checked only when it is written.
   - **Problem:** loading never checks the level still matches. `peak-game-fixes` is editing Meat Boy levels
     now (The Gap, The Bit); the old copies then differ in 25-30 cells beyond their change. A skipped operator's
     old folder also survives.
   - **Fix:** store the level file's hash in `mutant.json` and skip on mismatch; `build` deletes skipped
     operators' folders. Until then, step 8 regenerates every mutant first (stage 1); today's committed 241
     mutants match the committed levels exactly (regenerated and diffed).
   - **If we skip it:** a mutant is compared on an old layout while the base plays the new one.

10. **Mario's grid sensor shows the wrong things** (`code/games/platformer_core.py:1414-1496`) — open (code/games)
   - **What this is:** the "grid" sensor arm of the rays-vs-grid ablation.
   - **Problem:** Koopas and fire bars are invisible, power-ups read as the goal, `O` pits count as floor.
   - **Fix:** classify by `type_id`, add fire-bar balls, exclude pit tiles from floor.
   - **If we skip it:** the sensor-ablation figure is wrong for Mario.

## Should fix

11. **A resubmitted task retrained everything it had finished** (`balance.py:521`, `gasweep.py:390`) — fixed
   - **Problem:** every job started a fresh population, so a timed-out 12-level task redid all 12 levels, and
     each gasweep call reran the base config.
   - **Fix:** finished probes are skipped (delete a probe dir to redo it). This makes Narval resubmits cheap.

12. **A side GA sweep rewrote `ga_best.yaml` from its few reports** (`gasweep.py:338`) — fixed
   - **Problem:** `gasweep --out runs/_test` erased the other games from the committed file.
   - **Fix:** only a sweep into `runs/balance` publishes it.

13. **Playtest and relay CSVs could vanish or go stale** (`ast_eval.py:321`, `relay.py:304`) — fixed
   - **Problem:** the relay deleted its last results before playing; `play` deleted then rewrote; when no agent
     could play, old rows survived as current.
   - **Fix:** one `episode_log.rewrite` (temp file and one rename), used by play, random and relay; tested.

14. **The win-rate window counted the first-win generation only for late solvers** (`balance.py:145`) — fixed
   - **Fix:** always the WIN_WINDOW generations after the first win (that generation alone when the budget ends there).

15. **The WebSocket accepted any website** (`server.py:107`, `cameras.py:403`) — fixed
   - **Problem:** any open page could switch a running training's level or take control of a genome.
   - **Fix:** only the dashboard's own origin (or a non-browser client) may connect.

16. **Route maps showed one seed's wins and another's deaths; Mega Man had none** (`report.py:372`) — fixed
   - **Fix:** seeds are taken in turn, from the report's own probe dirs (Mega Man's live under `runs/ast`).

17. **Mega Man's Fisher test pooled six personas against five; top-cause ties flipped by row order** (`ast_metrics.py:199, 304`) — fixed
   - **Fix:** compare only personas both sides played; a tie of top causes counts as no change when they overlap.

18. **11 tests read trained data that this branch's `RESET DATA` (`30a070eb4`) removed** — fixed
   - **Fix:** 4 now write their own small reports; 7 skip until trained runs exist (step 8 brings them back).
     `test_the_balance_tab_lists_the_levels_no_agent_trained_on` asserts which levels are untrained today:
     update it after the rerun trains every level.

19. **`run_all.sh sweeps` built the whole site in each of 18 array tasks** (`run_all.sh:41`) — fixed
   - **Problem:** 18 concurrent builds, each parsing gigabytes of `state.json`.
   - **Fix:** an array task skips it; the stage after the array builds it once.

20. **The GA sweep crashed on Windows when its output went to a file or pipe** (`gasweep.py:404`) — fixed
   - **Problem:** it printed `≈`, which cp1252 cannot encode (found by the smoke run; Narval's UTF-8 is fine).
